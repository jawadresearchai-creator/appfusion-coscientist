# v0.12 Lock Audit and Corrections

**Audit date:** 2026-09-02  
**Inputs:** v0.11 Security, Autonomy & Clean-Room Closure Draft and v0.12 Lock-Candidate Errata

## Result

The v0.12 amendments are architecturally sound after the corrections below. They close material ambiguity in clean-room transfer, milestone claims, iOS acceptance, hostile-runner policy, autonomy labels, engine feasibility, evidence invalidation, evaluation, budgeting, and release signing.

The implementation target is `FOUNDRY_VERTICAL_SLICE_ALPHA`. This is implementation of the AppFusion system, not implementation of a synthesized Product, so it does not bypass the future Product Blueprint approval gate.

## Corrections applied

1. **Cloud authority and optional local execution.** GitHub repositories, cloud CI, and private Drive storage are canonical. ChatGPT web, Codex desktop, a coordinator API, and a local CLI are interchangeable control adapters. No local path or active desktop session is required by the canonical workflow.
2. **Outcome vocabulary.** Section 3.1 used undeclared `FAILED_BLOCKED_ENVIRONMENT`. It is normalized to the declared `BLOCKED_ENVIRONMENT` outcome. Run state and stage outcome remain distinct.
3. **Immutable approval lifecycle.** An immutable `ApprovalEnvelope` can only represent the approval as created. Revocation and supersession are new append-only `ApprovalEvent` records; an envelope is never edited in place.
4. **Three core artifacts plus derived attestation.** The three review/audit artifacts are `FoundryDecisionDossier`, `ProductBlueprint`, and `ApprovalEnvelope`. `ProductApprovalAttestation` is a fourth, derived, sanitized transfer object and is explicitly named as such.
5. **Web-session truthfulness.** ChatGPT web can act as an interactive control surface through installed connectors. It does not by itself prove `SYSTEM_V1_UA`. Unattended reasoning after every chat is closed requires the separately deployed persistent coordinator and authorized model budget.
6. **Untrusted runner feasibility.** GitHub-hosted CI is permitted for trusted control-plane tests and metadata registration. Untrusted APK parsing/execution remains `BLOCKED_SECURITY_ENVIRONMENT` until the selected runner demonstrates egress and metadata isolation. The implementation must not claim that `permissions: {}` alone creates a malware sandbox.
7. **Drive-to-CI bridge.** ChatGPT/Drive connector access is not automatically available inside GitHub Actions. The cloud intake adapter requires Google workload identity or another approved object-store credential. Absence produces `BLOCKED_AUTHORIZATION`, never a local fallback requirement.
8. **System lock versus Product approval.** System Blueprint v1.0 is locked by this implementation authorization. Every future generated `ProductBlueprint` still requires explicit hash-bound user approval.
